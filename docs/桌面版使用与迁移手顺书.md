# Showroom 管理：Mac 桌面版使用与迁移手顺书

版本：0.4.0 · 更新日期：2026-09-21

## 1. 现在怎么打开

本机应用安装位置：`~/Applications/Showroom 管理.app`。

在访达的个人“应用程序”文件夹中双击 **Showroom 管理**。可以把图标拖入 Dock，之后直接点击打开。

- 不需要启动终端或手动打开浏览器。
- 不需要管理页面的账号密码；应用自动建立仅本次启动有效的本地会话。
- 原 Python 后台、网页和连接能力都打包进 App，不需要在新电脑另装 Python。
- 只监听本机的随机端口，不占用固定的 8091 端口，不开放局域网或公网访问。
- 关闭窗口即退出本地后台。云端的监控、录制、视频处理与上传继续运行。
- 正在保存成员时先等待结果，应用会阻止正常关闭窗口；强制退出、断电等仍可能中断操作，恢复后应重试原操作。

全新安装及迁移导入后的默认状态为**演示模式**。演示新增、修改只保存到本机，不会进入真实录制。

## 2. 哪些电脑可以使用

本次交付的安装包适用于 **Apple Silicon Mac（M 系列），macOS 15 及以上**，已在当前 macOS 15.7.3 的 Mac 实际验证。

换到满足这些条件的 Mac，可以复制同一 App 并导入迁移包。Intel Mac 或低于 macOS 15 的系统，需要在相应环境重新打包并验证，不能直接保证当前二进制兼容。Windows 版按本次要求暂停，没有交付 Windows 安装包。

App 为本地自签名构建，没有 Apple Developer ID 公证。新电脑如果显示系统验证提示，应由使用者核对应用来源后按系统提供的方式处理；不要关闭整机安全保护。

## 3. 程序与数据分开放在哪里

| 内容 | 位置 |
|---|---|
| App 程序 | `~/Applications/Showroom 管理.app` |
| 应用配置和私有文件 | `~/Library/Application Support/Showroom Console/` |
| 配置 | 上述目录的 `settings.json` |
| 数据库凭证、SSH 私钥、已信任主机记录 | `secrets/` |
| Oracle Wallet | `wallet/` |
| 演示数据和添加操作记录 | `state/onboarding/demo/` |
| 真实添加操作记录 | `state/onboarding/oracle/` |
| 3C 原 jdex 备份 | 远端 `/home/ubuntu/showroom-admin-backups/`，第一次真实写入时才创建 |

`~` 代表当前 Mac 用户的主目录，换用户名无需手动替换旧电脑路径。

通过设置页导入的凭证、Wallet 和三台实例的 SSH 密钥保存到应用专用目录。配置使用目录内副本后，App 不依赖原录制项目或原私钥路径；已信任主机文件需包含对应服务器的记录。

应用配置、Wallet 和密钥都不放进 `.app` 安装包。复制 App 只能迁移程序，**迁移个人配置必须另外导出迁移包**。更新 App 时保留用户数据目录即可。

## 4. 首次连接真实数据库

打开左侧 **设置与迁移**。

Mac App 已内置 Oracle Instant Client，使用 `cwallet.sso` 自动登录 Wallet，**无需输入 Wallet 密码**。客户端随 App 移动，不需要安装系统级 Oracle 环境。

1. 确认设置页显示“使用自动登录 Wallet（cwallet.sso）”。
2. 点击“检查连接”。这一步仅检查 SSH、索引目录以及 Oracle 连接/成员查询，不修改服务器文件或数据库。
3. 连接检查通过后，将“下次启动模式”改为“真实数据库”，保存。
4. 点击“退出应用”，再双击 App 打开。
5. 核对页面显示 Oracle，确认成员与状态符合真实数据库。

如果在其他电脑首次配置而没有迁移包：

- 填写数据库账号、密码和连接别名。
- 选择包含 `tnsnames.ora` 和 `cwallet.sso` 的 Wallet 文件夹。
- 填写 3C 地址和 SSH 用户名，选择 SSH 私钥及已信任主机文件 `known_hosts`。
- 核对索引目录 `/home/ubuntu/showroom/index`。
- 保存，检查连接，重新打开应用。

选择文件或 Wallet 文件夹时会把副本导入应用目录，不会移动原文件。数据库账号和密码需一起填写；均留空则保留现有凭证。此界面填写的数据库账号默认也用于成员写入；高级的独立读写账号仍可在配置文件中指定。

SSH 主机指纹检查保持开启。如果服务器换了主机密钥，先核实新指纹，再导入正确的已信任主机记录，不能直接忽略校验。

## 5. 写入开关与现有上传规则

真实添加与修改需要写连接账号具有 `MEMBERS`、`YOUTUBE_CONFIGS`、`YOUTUBE_TAGS` 等对象的相应查询与写入权限。首次安装及迁移导入后写入开关默认关闭，需要在“设置与迁移”中勾选“开启真实成员添加与修改”、保存并重新打开应用。

本应用不会修改或重启云端原程序；保存成功表示配置已保存，实际加载与录制时机继续由原程序决定。

数据库 Team 和 jdex 日文队伍可以分别填写。Team 必须按现有成员的格式填写，原上传脚本使用它判断 AKB48 账号。

**现有上传规则：**

- 本地原脚本按英文名 `Hashimoto Haruna` 选择主账号，其他 Team 含 `AKB48` 的成员选择副账号；第三账号上传目前禁用。
- `USE_PRIMARY_ACCOUNT` 会保存到数据库，但目前原脚本不使用它选账号。
- `PRIVACY_STATUS` 会保存到数据库，但目前原脚本使用全局公开状态。
- 标题按固定文字使用；描述支持 `{upload_time}`，普通花括号写成 `{{` 和 `}}`。
- 标题、描述、标签、播放列表留空时，现有上传脚本可能沿用全局默认，不代表强制清空上传结果。
- 此功能配置后续上传，不修改已上传的视频，也不触发 YouTube 发布。

## 6. 添加、修改成员与失败恢复

### 添加成员

1. 打开“添加成员”，确认当前是演示还是 Oracle。
2. 填写成员 ID、姓名、组合、房间号、网址最后一段、数据库 Team 和索引队伍。
3. 选择现有 jdex 文件，检查大小写和特殊分组（例如 Team 8）。
4. 填写 YouTube 标题、描述、分类、播放列表、标签等；不勾选“保存上传配置”则不新增专属上传配置。
5. 点击“检查并预览”，检查录制索引和上传配置，确认添加。
6. 在成员目录中核对资料，并按原有方式观察监控与录制结果。

新增顺序：数据库事务中暂存停用成员及上传配置、标签 → 3C 备份并原子追加 jdex → 设置成员启用状态。上传配置/标签保存失败时，该数据库事务回滚，不留下半份新成员配置。

### 修改已有成员

1. 打开“成员目录”，搜索成员，进入详情，点击“编辑资料与上传配置”。
2. 修改范围默认“仅上传配置”，此模式不修改 jdex。即使没有找到索引条目，也能修改上传配置。
3. 需要修改资料时选择“成员资料、录制索引与上传配置”。支持日文姓名、组合、数据库 Team、网址标识、启用状态，以及索引队伍和优先级。
4. 成员 ID、房间号、英文名关联历史记录及视频文件，固定为只读；索引文件不自动迁移。
5. 点击“检查并预览”，查看前后差异，再点“保存修改”。保存后点击“查看保存结果”。
6. 最近修改记录位于“添加成员”页面下方。预览会生成待确认的操作记录，尚未点击保存不会改变数据库或索引。

编辑检查打开页面后是否有其他修改；资料或索引不匹配时拒绝覆盖。对涉及索引的编辑，先锁定数据库成员行、备份并替换索引，然后在同一个数据库事务中保存成员和上传配置。原条目的自定义索引字段与其他成员条目保留。

**数据库与远端文件不是一个事务。** 如果索引写好后数据库保存失败，会保留未完成记录，界面不会显示成功；恢复连接后重试原操作，让数据库与索引收敛。不要新建同一操作、删除日志或用整个旧索引文件覆盖回退。数据库提交响应丢失时，重试会先检查当前值，避免重复写入。

保持一台管理电脑操作，避免与外部手工 SQL 或索引编辑同时修改同一成员。停用成员不代表立即结束已启动的录制。本管理工具不会自动分配实例、重启云端服务或删除成员。

## 7. 换 Mac：完整迁移步骤

### 在旧电脑导出

1. 等待所有添加操作完成。存在失败记录时，尽量先处理；迁移包也会带走这些操作记录。
2. 打开“设置与迁移”下方“换电脑 · 加密迁移”。
3. 设置至少 12 位的迁移密码，并再次输入。
4. 点击“导出迁移包”，选择应用数据目录以外的位置，例如“文稿”。
5. 保存 `.srbackup` 文件，单独保管密码。
6. 退出旧电脑的 App，避免两台电脑同时添加成员。

迁移包包含配置、数据库凭证、Wallet、SSH 私钥和本地操作记录，不包含录制视频、生产 Oracle 数据库本体或 3C 上的索引备份。使用 AES-GCM 加密并校验完整性；密码遗失后无法解密。不要把密码和迁移包放在同一份公开信息里。

### 在新电脑导入

1. 检查新 Mac 符合第 2 节的架构和系统要求。
2. 解压程序发行包，把 `Showroom 管理.app` 复制到新电脑的应用程序文件夹。
3. 打开 App；首次为演示模式，无需管理页面密码。
4. 进入“设置与迁移”，输入旧电脑导出时的迁移密码。
5. 点击“导入迁移包”，选择 `.srbackup` 文件，确认导入。
6. 当前本机数据会先保留到同级 `Showroom Console-before-import-…` 目录；成功后 App 自动退出。
7. 重新打开，检查“设置与迁移”中凭证已导入，并执行连接检查。
8. 核对操作记录。确认无误后再切换到真实模式；真实添加开关需另行开启。

导入不会自动开启生产写入，也不会复用旧会话。错误密码或校验失败时，不切换当前配置。

新电脑仍需要能够访问 OCI 数据库和 3C。数据库网络白名单、密钥有效期、服务器地址变化属于外部条件，不能仅靠复制程序保证连通；检查未通过时先处理对应网络或凭证问题。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| App 显示“已在运行” | 切换到已有窗口；应用对同一数据目录只允许运行一个实例 |
| 没有登录页面 | 正常。只有 App 持有本次启动的会话凭据，手动访问随机端口不会自动登录 |
| 仍提示 Wallet 密码缺失 | 确认打开的是 0.4.0 Mac App；源码轻量模式仍可能需要该密码 |
| 保存设置后仍是旧模式 | 退出并重新打开 App |
| 新电脑找不到旧路径 | 使用迁移包导入；不要直接复制旧的网页版本 `local_settings.json` |
| 添加失败或退出中断 | 查看原操作，恢复连接后重试，不要重复新建 |
| 保存成功但没有录制 | 检查 1C 成员刷新、3C 索引加载以及实例分配 |
| 导出提示外部绝对路径 | 通过设置页导入相关凭证/Wallet，让配置使用应用目录里的副本 |
| 迁移密码错误或文件损坏 | 保留旧电脑和原迁移包；应用不会跳过解密校验 |
| Oracle 查询失败 | 核对账号、Wallet 文件、DSN 和数据库网络限制；界面不会自动把失败查询替换成演示结果 |

不要用旧 jdex 备份整文件覆盖新文件来回退某一个成员；其他新增可能会被一起覆盖。回退前需要核对具体操作及数据库/文件差异。

## 客户端与重新打包

Mac App 包含 Oracle 官方 Instant Client Basic 23.26.2 ARM64（附带 BASIC_LICENSE），不包含个人 Wallet 或数据库凭证。构建时指定 `SHOWROOM_BUILD_ORACLE_CLIENT` 为已解压官方客户端目录，再运行 `tools/build_mac.py`。应用通过连接描述符指定当前 Wallet 路径，避免导出 Wallet 内 Linux 路径影响本机或迁移后的连接。旧版 0.2.0 压缩包不含客户端，请使用 0.4.0。

本版也修复了 Finder 启动时 ASCII 语言环境导致中文应用路径无法加载的问题；启动时仅设置应用自身的字符编码环境，不修改系统语言。0.3.0 的自动测试与隔离演示验证涵盖新增上传配置、编辑、冲突检测、数据库回滚、SSH 响应丢失与恢复。

## 0.4.0：中日文、成员模板与日志工作台

页面精简为「添加成员」「成员列表」「日志工作台」「设置与迁移」四个入口。右上角可切换中文／日本語，选择保存在本机并随加密迁移包转移。日志内容及成员资料保持原文。

添加页读取数据库中 `shiratori_sari`（白鳥 沙怜）和 3C 上对应 jdex 条目作为默认模板。复制组合、Team、索引队伍、优先度、启用状态及 YouTube 上传配置；成员 ID、姓名、房间号、URL 末尾和播放列表 ID 留空。输入新成员日文姓名时，说明和标签中的模板姓名自动替换；手动修改过的字段不再自动覆盖。模板当前为停用，按需勾选启用。播放列表留空仍可能由原上传脚本使用全局默认播放列表，不代表禁止加入任何播放列表。标题留空同样沿用原脚本默认规则。

日志工作台使用 SSH 只读访问三台机器的 `/home/ubuntu/logs`，不启动或停止录制，不从日志推断录制状态。点击 1C／3C／4C，选择文件和读取行数，即可查看原始日志。支持手动刷新、每 10 秒自动刷新（默认关闭）、跟随末尾和当前已读取内容的文本筛选。自动刷新只在工作台可见时运行。

- 每次最多读取文件末尾 256 KB、1,000 行，避免下载大文件。
- 文件列表包含根目录及最多两层子目录的普通文件，最多显示 500 个；压缩历史日志不显示。
- 拒绝路径越界、符号链接、管道及包含空字节的二进制文件。
- 文件轮转或网络中断后刷新列表重试；读取失败时保留上次内容并显示错误。
- 三台实例的 SSH 地址、用户名、私钥可在设置中的「更多连接设置」调整；共用已信任主机文件并严格校验指纹。变更连接后重启应用。

1C／4C 私钥分别存入本机 `secrets/1c.key`、`secrets/4c.key`，3C 继续使用 `secrets/3c.key`。这些文件只在本机数据目录和用户加密导出的迁移包中，不进入应用安装包。换 Mac 后导入迁移包即可恢复连接资料，导入后仍默认演示模式、写入关闭；确认连接后自行切回真实模式。
